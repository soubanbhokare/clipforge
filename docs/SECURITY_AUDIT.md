# CLIPFORGE — Phase 13 Security Audit (§4)

**Scope:** Security verification against OWASP ASVS 5.0.0 / OWASP Top 10:2025, adapted to the
actual architecture: React 18 + TypeScript + Vite frontend (`src/`), Express + TypeScript
backend (`server/src/`), SQLite via `node:sqlite`, DB-backed in-process workers (no
PostgreSQL/Redis/BullMQ/Docker), server-side email outbox when SMTP is unconfigured, no
platform OAuth credentials present, payments flag-disabled, local faster-whisper STT.

**Method:** Read-only code audit of `src/` and `server/src/` (no application code was
modified), plus one controlled live probe against a throwaway server instance on port 3999
with a temporary database and temporary media/processing/report/avatar/export/logo dirs
(test accounts only; temp dir deleted afterwards). The e2e suites were **not** run as part
of this audit. Evidence below is `file:line` plus what was observed; live-probe results are
marked **[live]**.

**Nature of this document — read first:** This is an **internal code audit**. It is **NOT a
penetration test and NOT a certification** (not an ASVS certification, not a SOC/ISO/PCI
attestation, and not a guarantee that the system is free of vulnerabilities). No external
attacker simulation, no fuzzing campaign, no dependency-vulnerability scan, and no review of
hosting, TLS termination, OS, or network configuration was performed. Verdicts describe the
controls as implemented in the code and observed in the controlled probe, at the time of
the audit (2026-11-02).

**Headline result:** No Critical and no High findings. The core authentication, session,
token, authorization, SQL-injection and command-execution surfaces are genuinely strong
(parameterized SQL throughout, arg-array process execution with no shell, AES-256-GCM token
storage, replay-protected TOTP, ownership checks on object routes). The findings are
2 Medium, 7 Low, 5 Info — mostly hardening gaps (missing CSP/HSTS, SVG handling, rate-limit
coverage) rather than broken controls.

Checklist totals: **23 areas — 15 PASS, 8 PARTIAL, 0 FAIL**, plus N/A items listed at the
end of the checklist.

## 1. ASVS-style checklist

### A. Authentication & session (ASVS V2 / V3)

| # | Area | Verdict | Evidence |
|---|------|---------|----------|
| 1 | Password storage | **PASS** | Argon2id via `@node-rs/argon2` with library defaults and no weakening options (`server/src/app.ts:23,413,720`; `server/src/account.ts:728`). | 2 | Email verification flow | **PARTIAL** | Token mechanics are strong: 32-byte random token, only SHA-256 hash stored, 24 h expiry, superseding older tokens, atomic single-use consume (`app.ts:219-248,473-501`). **But** enforcement is opt-in: `REQUIRE_EMAIL_VERIFICATION` defaults to `false` (`server/src/config.ts:26-27`), the login gate only applies when it is true (`app.ts:608`), and registration immediately opens a full session (`app.ts:462`). See F-05. |
| 3 | Session management | **PASS** | Cookie holds a 32-byte random token; only its SHA-256 hash is stored server-side with expiry (`app.ts:138-172,193-217`). **[live]** In `NODE_ENV=production` the `cf_session` Set-Cookie carried `HttpOnly; Secure; SameSite=Lax; Max-Age=43200` (12 h; remember-me 30 d per `config.ts`). Logout deletes the session row (`app.ts:664-671`). Password reset revokes **all** sessions (`app.ts:741`); password change and email change revoke all *other* sessions (`account.ts:728-733` area, `account.ts:556-625` area). Suspended and deletion-pending accounts are rejected in `readSession` even with a live cookie (`app.ts:158-164`). Per-session revoke is ownership-scoped (`account.ts:787-805`). Sessions list exposes only the stored hash id, not a usable token. |
| 4 | MFA (TOTP / recovery codes) | **PASS** | Real RFC 6238 TOTP (HMAC-SHA1, ±1 step window, timing-safe compare) in `accountCore.ts:351-424`. Replay protection: matched step is persisted (`user_totp.last_used_step`, migration v13) and a step ≤ last used is rejected — `verifyTotpFresh` in `account.ts:93-112`, used at login, confirm and disable (`account.ts:366,919,990`). MFA setup/disable/regenerate require current-password re-authentication (`account.ts:866-1057`). |
| 5 | Password reset / token handling | **PASS** | Reset tokens follow the same pattern as verification: hashed at rest, 30-min expiry, supersede prior tokens, atomic consume before the password changes, all sessions revoked, audit + login-event records written (`app.ts:681-761`). Forgot-password always returns the same generic response whether or not the account exists (`app.ts:688-706`). Login returns one generic error for unknown email and wrong password, and pays the Argon2 cost against a dummy hash for unknown emails to blunt timing enumeration (`app.ts:250-256,542-570`). Email-change is a verified flow: token bound to the account (403 if another account presents it), old address notified, other sessions revoked (`account.ts:485-625`). |

### C. API & input security (ASVS V5 / V13)

| # | Area | Verdict | Evidence |
|---|------|---------|----------|
| 8 | Input validation (zod) | **PARTIAL** | Broad zod coverage: ~150 `safeParse` call sites across route modules (account 22, broll 16, captions 9, admin 8, publishing 7, tracking 6, app/studio/editor 5 each, analytics 4, analysis/export 2/1) with tight bounds (string max lengths, numeric ranges, enums, `.strict()` on several account schemas). | 12 | Security headers | **PARTIAL** | Manual "helmet-lite" sets `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy: same-origin`, and `x-powered-by` is disabled (`app.ts:270-283`). **[live]** `Content-Security-Policy`, `Strict-Transport-Security` and `Permissions-Policy` were **absent** from responses. | 13 | Error handling & leakage | **PARTIAL** | The global handler returns generic bodies and never leaks stack traces or SQL detail (`app.ts:850-863`); **[live]** malformed JSON returned the generic `400 {"error":"Invalid request body."}`. Full error objects are written to server console logs only. Several provider-facing routes return the provider's own error message to the job owner (e.g. `publishing.ts` `ProviderError` messages) — acceptable owner-scoped operational detail, already passed through `providers.ts` `redact()`. |
| 14 | SQL injection | **PASS** | ~997 `.prepare()` call sites; values are bound parameters throughout. Every string-interpolated SQL fragment found is built from **fixed clause strings** with bound values (e.g. `studio.ts:441-467`, `analyticsCore.ts:92-99`, `account.ts:1972-1981`, `admin.ts:463-476`), an **allow-listed** ORDER BY (`studio.ts:425-433`, `analysis.ts:1459-1468`), a hard-coded table-name union type (`app.ts:219-241` — `email_verification_tokens \| password_reset_tokens` only), or internal typed patch objects whose keys come from server-side call sites (`publishing.ts:782-833`, `analytics.ts:267-273`). `db.exec()` is used only for static migration SQL, PRAGMAs and transaction control (`db.ts:1911-2034`); `ensureColumn` interpolates identifiers that come only from migration code (`db.ts:1969-1974`). No user input reaches SQL text. |
| 15 | Output encoding / XSS | **PARTIAL** | Frontend: React rendering throughout, **zero** `dangerouslySetInnerHTML`/`innerHTML` in `src/` (grep-verified) — no DOM XSS sink found. Caption text is escaped for ASS/libass (`captions.ts:408-417` `assText`), and provider payloads are redacted before persistence (`providers.ts:44-60`). ## 3. What was verified live (controlled probe summary)

Throwaway instance: port 3999, `NODE_ENV=production`, temp SQLite DB and temp
media/processing/reports/avatars/exports/logos dirs, test accounts only; instance killed
and temp dir deleted after the run.

- Security headers present: `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy:
  no-referrer`, COOP `same-origin`; **absent:** CSP, HSTS, Permissions-Policy (F-03).
- CORS: evil origin → no `Access-Control-Allow-Origin`; exact dev origin → echoed with
  credentials allowed.
- CSRF: mutation without header → **403**; multibyte same-character-length header → **500**
  (F-06a).
- Session cookie (production): `HttpOnly; Secure; SameSite=Lax; Max-Age=43200`. CSRF cookie:
  `Secure; SameSite=Lax`, not HttpOnly (by design).
- Login: unknown email → generic **401**; rate limit at max=3 → sequence `401,401,401,429,429`.
- Registration: success → **201** with immediate session; duplicate email → **409** naming
  the conflict (F-04).
- Unauthenticated `GET /api/projects` → **401**.
- Malformed JSON → generic **400**; 150 kb JSON body → **500** (F-06b).
- SVG brand asset with a `<script>` element → upload **201**, stream **200**
  `image/svg+xml`, script intact, no disposition/CSP (F-01); cross-user stream → **404**
  (IDOR control working).
